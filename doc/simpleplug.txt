1. INTRODUCTION                                             *simpleplug-intro*

SimplePlug installs, updates and cleans Vim plugins. Vim9 script owns the
registry, lazy loading and the progress UI; a resident Rust (Tokio) daemon runs
every git operation in parallel, so Vim never blocks on the network.

Requires Vim 9.0+ with |+job|, |+channel| and |+timers|, plus git in $PATH.
Run ./install.sh once to compile the daemon (Rust 1.88+).

==============================================================================
2. DECLARING PLUGINS                                      *simpleplug-declare*

Wrap declarations between simpleplug#Begin() and simpleplug#End(): >

    call simpleplug#Begin('~/.vim/plugged')
    call simpleplug#Plug('tpope/vim-surround')
    call simpleplug#Plug('rust-lang/rust.vim', {'for': 'rust'})
    call simpleplug#End()
<
simpleplug#Begin() takes an optional directory; without one it uses
|g:simpleplug_dir|. It also clears any lazy-load state from a previous run, so
re-sourcing your vimrc is safe. Plugins already lazy-loaded in this Vim session
are left alone: their stubs are not reinstalled over the real command and
mapping the plugin defined, and their runtime directory stays on
'runtimepath'. Sourcing such a plugin again would only hit its own reload
guard and define nothing, so anything torn down here could never be rebuilt.

simpleplug#End() adds every installed plugin to 'runtimepath' (including its
after/ directory), sources non-lazy plugins, and enables filetype and syntax.
For a plugin with `rtp`, the configured subdirectory is used instead of the
checkout root.

3. PLUGIN OPTIONS                                         *simpleplug-options*

simpleplug#Plug() accepts a repository shorthand ('owner/name'), a full URL, or
a local path, plus an optional dictionary:

  as        Install under a different directory name.
  dir       Use this exact directory instead of one under g:simpleplug_dir.
  rtp       Vim runtime below the checkout root, for example "vim" or
            "editors/vim". Must be relative and may not contain ".." or a
            comma.
  branch    Track this branch.
  tag       Pin to this tag.
  commit    Pin to this exact commit.
  do        Shell command to run after install or update (a post-hook).
  frozen    Never update this plugin.
  for       Load only for these filetypes (string or list).
  on        Load on this command or <Plug> mapping (string or list).

`tag` and `commit` make the plugin appear as `pinned` in |:PlugStatus|. Shallow
clones fetch the requested object directly, falling back to full history only
when that fails.

`for` sources the plugin's ftdetect/ files eagerly, so a filetype the plugin
itself defines can still trigger the load. `on` with a <Plug> mapping installs
a stub that loads the plugin and replays the key on first use.

`rtp` affects 'runtimepath', eager/lazy script loading, ftdetect and helptags.
Git operations, hooks, snapshots and cleanup still operate on the checkout
root. This makes monorepos and multi-editor repositories first-class without
weakening SimplePlug's directory safety checks. Existing runtime directories
are resolved before every load; a symlink whose final target leaves the
checkout is rejected. Its after/ directory is added independently even when
the main runtime entry was already present.

If an `on` or `for` trigger fires while its runtime directory is temporarily
missing, SimplePlug reports the path and keeps the plugin unloaded. Command
and mapping stubs remain usable, and FileType triggers remain registered, so
restoring the directory and repeating the trigger retries the load.

4. COMMANDS                                              *simpleplug-commands*

                                                                *:PlugInstall*
:PlugInstall[!] [name ...]
        Install missing plugins. With names (completed from the registry),
        only those are installed.

        With [!] the command does not return until the operation has finished
        (or |g:simpleplug_sync_timeout| expires), which is what makes a
        headless bootstrap work: >

            vim -es -u vimrc +'PlugInstall!' +qall
<
        CTRL-C abandons the wait and stops the operation. Without [!] the
        install runs asynchronously, exactly as before.

        A checkout left behind by an interrupted clone counts as missing. git
        creates the destination and its .git before the objects finish
        transferring, so quitting Vim or running |:PlugStop| during an install
        leaves a directory that is not a usable repository. SimplePlug detects
        it — the daemon requires a resolvable HEAD, not merely a .git — and
        removes and re-clones it instead of reporting "already installed"
        forever.

                                                                 *:PlugUpdate*
:PlugUpdate[!] [name ...]
        Update plugins, skipping frozen and pinned ones. A plugin whose
        directory is missing, or left half-written by an interrupted clone, is
        cloned rather than pulled. [!] waits for completion, as with
        |:PlugInstall|.

                                                                  *:PlugClean*
:PlugClean[!]
        Remove unregistered plugin directories. Only direct children of
        |g:simpleplug_dir| that contain a .git directory are considered;
        symlinks and ordinary data directories are left alone. With [!] it
        does not ask for confirmation.

                                                                 *:PlugStatus*
:PlugStatus
        Show every plugin with its state and the date and subject of its most
        recent commit.

                                                               *:PlugSnapshot*
:PlugSnapshot [file]
        Write the exact commit of every plugin to a snapshot file. Defaults to
        g:simpleplug_dir/simpleplug.snapshot.json. The legacy JSON object shape
        ({plugin-name: full-oid}) is retained. A private 0700 staging directory
        is atomically claimed beside the target on the same filesystem; the
        complete file is written inside it and atomically renamed, so a failed
        write leaves the previous snapshot intact. Pre-existing staging names
        are skipped without following them. A snapshot target that is itself a
        symbolic link is refused.

                                                           *:PlugSnapshotDiff*
:PlugSnapshotDiff [file]
        Compare registered local checkouts with a snapshot without starting
        the daemon, accessing the network, or changing the snapshot. The
        complete legacy object is validated before any checkout is inspected
        or output is printed. Results are sorted by plugin name and distinguish
        matched entries, commit drift, a missing checkout, a non-Git directory,
        an unreadable HEAD, a registered plugin absent from the snapshot
        (unlocked), and an unregistered snapshot entry (orphaned).

                                                                *:PlugRestore*
:PlugRestore [file]
        Check every plugin out to the commit recorded in a snapshot.
        Validation happens before the daemon starts: the root must be an
        object, every entry must have the expected type, and each commit must
        be a full 40-digit SHA-1 or 64-digit SHA-256 hexadecimal object ID.
        Existing snapshots produced by earlier SimplePlug versions use this
        same shape and remain readable.

                                                                   *:PlugHook*
:PlugHook {name}
        Re-run a single plugin's `do` post-hook.

                                                                   *:PlugStop*
:PlugStop
        Stop the daemon. It starts again on the next command.

See |simpleplug-daemon| for :PlugHealth, :PlugRestart and :PlugLog.

5. UI KEYS                                                     *simpleplug-ui*

Inside the progress window:

  q       close
  R       retry the failed plugins
  S       show status
  <CR>    open the plugin directory under the cursor
  d       view the plugin's incoming diff
  /       filter the list
  h, ?    toggle the key help

6. SCRIPTING                                            *simpleplug-scripting*

An install or update reports what it did, so nothing has to watch the progress
window to find out.

                                                       *SimplePlugComplete*
When an operation finishes — including when it fails, and when the daemon dies
mid-flight — SimplePlug sets |g:simpleplug_last_result| and then fires the
|User| autocommand SimplePlugComplete: >

    autocmd User SimplePlugComplete
      \ if g:simpleplug_last_result.errors > 0 | PlugLog | endif
<
                                                 *g:simpleplug_last_result*
The result of the most recent operation, a dictionary with these keys:

  mode       'install', 'update', 'status', 'clean' or 'hook'
  total      number of plugins the operation covered
  installed  newly cloned
  updated    moved to a new commit
  ok         already up to date, pinned, or hook-only
  frozen     skipped because of `frozen`
  removed    directories :PlugClean deleted
  errors     number of entries in `failed`
  failed     list of {name, message}, sorted by name
  elapsed    wall-clock seconds

                                                     *simpleplug#Await()*
simpleplug#Await([{timeout}])
        Block until the running operation finishes and return the same
        dictionary. {timeout} is in seconds; omitted or negative means
        |g:simpleplug_sync_timeout|. Returns the previous result immediately
        when nothing is running. This is what [!] on |:PlugInstall| uses.

                                                *simpleplug#LastResult()*
simpleplug#LastResult()
        The dictionary above, or an empty one if no operation has finished
        yet.

7. CONFIGURATION                                           *simpleplug-config*

                                                            *g:simpleplug_dir*
Plugin directory. Default: ~/.vim/plugged

                                                   *g:simpleplug_daemon_path*
Explicit path to the daemon binary. Default: '' (search 'runtimepath'/lib).

                                                          *g:simpleplug_debug*
Echo daemon traffic as it happens. Default: 0. |:PlugLog| is usually better —
it records everything without needing to be switched on in advance.

                                                   *g:simpleplug_auto_install*
Install newly declared plugins on VimEnter. Default: 1

                                                  *g:simpleplug_window_width*
Width of the progress window. Default: 88

                                                           *g:simpleplug_jobs*
Maximum parallel git operations, 1..64. Default: 8

                                                   *g:simpleplug_git_timeout*
Timeout in seconds for a single git operation. Default: 300

                                                  *g:simpleplug_hook_timeout*
Timeout in seconds for a post-hook. Default: 600

Both timeouts are re-read every time the daemon starts, so changing them takes
effect on the next |:PlugRestart| without restarting Vim.

                                            *g:simpleplug_activate_on_install*
Make a newly installed plugin usable in the running session instead of at the
next Vim start. Default: 1

When an install finishes, each plugin it reports as newly installed is added
to 'runtimepath' and its plugin/ and after/plugin/ scripts are sourced; its
ftdetect/ files are sourced too and already-open buffers are re-detected, so a
filetype the plugin introduces takes effect immediately. A plugin declared
with `for` or `on` only gets its triggers armed — it stays unloaded until one
of them fires, as usual. A plugin whose directory did not actually appear is
reported and left unloaded, and a script that throws is reported on that
plugin's row without stopping the rest of the batch.

Set it to 0 if you would rather restart Vim: sourcing third-party code at an
unusual moment can upset a plugin that assumes it loads before |VimEnter|.

                                                  *g:simpleplug_sync_timeout*
How many seconds [!] on |:PlugInstall| / |:PlugUpdate| and |simpleplug#Await()|
will wait before giving up. Default: 1800. The operation itself keeps running.

                                              *g:simpleplug_spinner_interval*
Progress window refresh interval in milliseconds. Default: 200

8. DAEMON SUPERVISION                                      *simpleplug-daemon*

The Rust daemon is managed by simplecore, the supervisor shared by the whole
simple* plugin suite. It is vendored into this repository at
autoload/simpleplug/core.vim; that file is generated, do not edit it in place.

What it guarantees:

- Liveness is always read from |job_status()|. job_start() returns a job
  object even when the exec itself failed, so a daemon that cannot start is
  never mistaken for one that is running.
- A superseded daemon's late exit callback cannot clear the state of the
  replacement that already took its place.
- Output still queued when you stop the daemon is discarded, so an explicit
  stop cannot be undone by an event that was already in flight.
- A daemon that dies is restarted automatically with exponential backoff.
  If it keeps crashing, the supervisor reports it once and stops trying
  rather than respawning forever; :PlugRestart re-arms it.
- Requests are correlated to replies by id and can time out, so a wedged
  daemon never leaves a callback hanging.

                                                                 *:PlugHealth*
:PlugHealth
        Report daemon path, run state, negotiated protocol and capabilities,
        uptime, crash and restart counts, whether the crash-loop breaker has
        tripped, the git executable, the plugin directory and both timeouts.

                                                                *:PlugRestart*
:PlugRestart
        Stop the daemon and start a fresh one. Clears the crash-loop breaker,
        so this is the way back after repeated failures.

                                                                    *:PlugLog*
:PlugLog
        Open the daemon transcript in a scratch buffer: start and exit events,
        restarts, protocol handshakes, send failures and stderr.


==============================================================================
DAEMON COMMAND LINE                                    *simpleplug-daemon-cli*

The daemon takes no arguments in normal use: the plugin starts it and speaks
JSON over its stdin and stdout.  For diagnosis it also answers: >

  simpleplug-daemon --version
  simpleplug-daemon --help
  simpleplug-daemon --self-test
<
--self-test checks the handshake reply serialises and prints "ok".
install.sh runs it on the freshly built binary before replacing a working one,
so a build that compiles but does not work never reaches lib/.

Every daemon in the simple* suite answers these three the same way.

VENDORED SUPERVISOR                                    *simpleplug-simplecore*

The daemon supervisor in autoload/simpleplug/core.vim, and the test harness
beside it, are vendored from the suite's shared .simplecore bundle rather
than written here — each plugin carries its own copy so that installing
this plugin alone is enough.  Do not edit those files in place: >

  make core-verify
<
checks each of them against the sha256 recorded in .simplecore.manifest and
fails the build when one has drifted.  `make check` depends on it.

The bundle lives at https://github.com/beamiter/simplecore.  To change the
supervisor, clone it beside the plugins, edit it there, and re-vendor: >

  git clone https://github.com/beamiter/simplecore ../.simplecore
  ../.simplecore/vendor.sh
<
