1. INTRODUCTION                                             *simpleplug-intro*

SimplePlug installs, updates and cleans Vim plugins. Vim9 script owns the
registry, lazy loading and the progress UI; a resident Rust (Tokio) daemon runs
every git operation in parallel, so Vim never blocks on the network.

Requires Vim 9.0+ with |+job|, |+channel| and |+timers|, plus git in $PATH.
Run ./install.sh once to compile the daemon (Rust 1.88+).

==============================================================================
2. DECLARING PLUGINS                                      *simpleplug-declare*

Wrap declarations between simpleplug#Begin() and simpleplug#End(): >

    call simpleplug#Begin('~/.vim/plugged')
    call simpleplug#Plug('tpope/vim-surround')
    call simpleplug#Plug('rust-lang/rust.vim', {'for': 'rust'})
    call simpleplug#End()
<
simpleplug#Begin() takes an optional directory; without one it uses
|g:simpleplug_dir|. It also clears any lazy-load state from a previous run, so
re-sourcing your vimrc is safe. Plugins already lazy-loaded in this Vim session
are left alone: not one of their triggers is re-armed — no command stub, no
mapping stub and no `for` autocmd — and their runtime directory stays on
'runtimepath'. Sourcing such a plugin again would only hit its own reload
guard and define nothing, so anything torn down here could never be rebuilt.
The `for` autocmd matters as much as the stubs do: re-arming it takes the
plugin's real command and mapping down on the first matching |FileType| event,
arbitrarily later in the session.

simpleplug#End() adds every installed plugin to 'runtimepath' (including its
after/ directory) and enables filetype and syntax. At startup Vim's own
'runtimepath' scan is what sources the non-lazy plugins, right after the
vimrc returns; when End() is called after |VimEnter| — re-sourcing a vimrc,
say — that scan is long over, so End() sources them itself. For a plugin with
`rtp`, the configured subdirectory is used instead of the checkout root.

3. PLUGIN OPTIONS                                         *simpleplug-options*

simpleplug#Plug() accepts a repository shorthand ('owner/name'), a full URL, or
a local path, plus an optional dictionary:

  as        Install under a different directory name.
  dir       Use this exact directory instead of one under g:simpleplug_dir.
  rtp       Vim runtime below the checkout root, for example "vim" or
            "editors/vim". Must be relative and may not contain ".." or a
            comma.
  branch    Track this branch.
  tag       Pin to this tag.
  commit    Pin to this exact commit.
  do        Shell command to run after install or update (a post-hook).
  frozen    Never update this plugin.
  for       Load only for these filetypes (string or list).
  on        Load on this command or key sequence (string, list, or a
            {keys, modes} dictionary; see |simpleplug-lazy-keys|).
  event     Load on this autocommand event (string or list; see
            |simpleplug-lazy-event|).
  dependencies
            Plugins that must be sourced before this one (list; see
            |simpleplug-lazy-deps|).

The scalar option types are checked during registration. as, dir, branch, tag,
commit and do must be strings; frozen must be a number or boolean. A malformed
plugin is rejected before a daemon batch starts. dir cannot contain a comma,
because comma separates entries in 'runtimepath'.

`tag` and `commit` make the plugin appear as `pinned` in |:PlugStatus|. Shallow
clones fetch the requested object directly, falling back to full history only
when that fails.

`for` sources the plugin's ftdetect/ files eagerly, so a filetype the plugin
itself defines can still trigger the load. `on` with a <Plug> mapping installs
a stub that loads the plugin and replays the key on first use.

                                                        *simpleplug-lazy-keys*
An `on` entry that is a bare string is a command name, unless it starts with
"<", in which case it is a key sequence mapped in Normal, Visual and
Operator-pending mode. To bind a trigger in other modes, write the entry as a
dictionary: >

    call simpleplug#Plug('user/completion', {'on': [
          \ {'keys': '<Plug>(complete)', 'modes': 'i'},
          \ {'keys': '<Plug>(cmdline)',  'modes': 'c'}]})
<
`modes` is a string of mode letters, any of "n", "x", "o", "i" and "c"; it
defaults to "nxo". An unknown letter is refused at registration rather than
mapped into nothing, and a plugin left with no usable trigger at all stays
eager. The stub uses |<Cmd>|, which does not change the current mode, so the
replayed key resolves to the plugin's own mapping in the mode the trigger
fired in.

                                                       *simpleplug-lazy-event*
`event` defers a plugin to an autocommand event. An entry is an event name,
optionally followed by one or more patterns (default "*"): >

    call simpleplug#Plug('user/snippets', {'event': 'InsertEnter'})
    call simpleplug#Plug('user/markdown', {'event': ['BufReadPre *.md',
          \                                          'BufNewFile *.md']})
    call simpleplug#Plug('user/notes', {'event': 'BufReadPre *.md *.org'})
<
Patterns after the event name are separated by blanks, and any one of them
wakes the plugin: they reach |:autocmd| joined with ",", which is how :autocmd
itself spells a list of patterns. A blank that belongs inside a single pattern
is escaped as "\ ", again exactly as :autocmd spells it: >

    call simpleplug#Plug('user/notes', {'event': 'BufReadPre /srv/my\ notes/*'})
<
An unknown event name is refused at registration — the alternative is a plugin
that never loads and never says why — and a plugin whose every event was
refused stays eager. Each event trigger is spent once and is not re-armed.

The occurrence that wakes a plugin arrives before the plugin has any handler
for it: the handler is registered by the sourcing that occurrence caused, and
Vim does not run autocommands that appear while it is already delivering an
event. SimplePlug therefore lets the delivery in progress continue into the
handlers the plugin just registered, so the plugin sees the occurrence that
woke it exactly once, as if it had been loaded before the event arrived. No
other listener for that event is run again. Set
|g:simpleplug_lazy_event_refire| to 0 to skip this, and the plugin starts
taking effect from the next occurrence instead.

                                                        *simpleplug-lazy-deps*
`dependencies` lists plugins that must be sourced before this one. Each entry
is a plugin name (the directory name, or whatever `as` set) or the repository
string the plugin was declared with. The dependency may be declared after the
plugin that needs it: >

    call simpleplug#Plug('user/ui', {'on': 'UiOpen',
          \                          'dependencies': ['plenary']})
    call simpleplug#Plug('user/plenary', {'as': 'plenary'})
<
'runtimepath' is ordered so that a dependency comes before its dependants, and
a lazily triggered plugin loads its dependencies before sourcing itself.

A dependency of an eagerly loaded plugin is loaded eagerly too, even when it
was declared with `for`, `on` or `event`: "before" is decided by 'runtimepath'
order during Vim's startup scan, and a trigger that has not fired yet never
gets there. Plugins that no dependency edge constrains keep their declaration
order, so adding the option does not reshuffle the rest of 'runtimepath'. A
cycle is reported by name and the plugins in it fall back to declaration
order; a dependency that was never declared is reported and skipped, and the
plugin that named it still loads.

`rtp` affects 'runtimepath', eager/lazy script loading, ftdetect and helptags.
Git operations, hooks, snapshots and cleanup still operate on the checkout
root. This makes monorepos and multi-editor repositories first-class without
weakening SimplePlug's directory safety checks. Existing runtime directories
are resolved before every load; a symlink whose final target leaves the
checkout is rejected. Its after/ directory is added independently even when
the main runtime entry was already present.

If an `on` or `for` trigger fires while its runtime directory is temporarily
missing, SimplePlug reports the path and keeps the plugin unloaded. Command
and mapping stubs remain usable, and FileType triggers remain registered, so
restoring the directory and repeating the trigger retries the load. An `event`
trigger is spent by the occurrence that fired it, missing directory or not, so
that plugin waits for the next |:PlugInstall| or the next Vim.

4. COMMANDS                                              *simpleplug-commands*

                                                                *:PlugInstall*
:PlugInstall[!] [name ...]
        Install missing plugins. With names (completed from the registry),
        only those are installed.

        With [!] the command does not return until the operation has finished
        (or |g:simpleplug_sync_timeout| expires), which is what makes a
        headless bootstrap work: >

            vim -es -u vimrc +'PlugInstall!' +qall
<
        CTRL-C abandons the wait and stops the operation. Without [!] the
        install runs asynchronously, exactly as before.

        A checkout left behind by an interrupted clone counts as missing. git
        creates the destination and its .git before the objects finish
        transferring, so quitting Vim or running |:PlugStop| during an install
        leaves a directory that is not a usable repository. SimplePlug detects
        it — the daemon requires a resolvable HEAD, not merely a .git — and
        removes and re-clones it instead of reporting "already installed"
        forever.
                                                       *simpleplug-re-clone*
        Re-cloning deletes a directory, so it happens only where all three of
        these hold:

        - git ran and gave a verdict. If git is not on 'path', times out, or
          refuses to read the checkout (a tree owned by another user, an
          unreadable or dangling .git), the plugin is reported as an error and
          the directory is left exactly as it is.
        - git confirmed .git is a repository and that its HEAD names no
          commit. A repository git cannot resolve at all is not assumed to be
          a broken one.
        - `git status` reports the working tree empty. An interrupted clone
          never got as far as checking anything out, so anything found there
          is yours: the plugin is reported as `dirty` and left alone.

        A clone of an upstream that simply has no commits yet also has an
        unborn HEAD, but it is a finished clone; it is reported as installed
        and left alone rather than re-cloned on every run.

                                                                 *:PlugUpdate*
:PlugUpdate[!] [name ...]
        Update plugins, skipping frozen and pinned ones. A plugin whose
        directory is missing, or left half-written by an interrupted clone, is
        cloned rather than pulled, under the conditions in
        |simpleplug-re-clone|. A plugin with uncommitted local changes is
        never updated or re-cloned; it is reported as `dirty` and left for you
        to resolve. If the upstream had no commits when the plugin was cloned
        and has some now, the update adopts them. [!] waits for completion, as
        with |:PlugInstall|.

                                                                  *:PlugClean*
:PlugClean[!]
        Remove unregistered plugin directories. Only direct children of
        |g:simpleplug_dir| that contain a .git directory are considered;
        symlinks and ordinary data directories are left alone. With [!] it
        does not ask for confirmation.

                                                                 *:PlugStatus*
:PlugStatus
        Show every plugin with its state and the date and subject of its most
        recent commit.

                                                                  *:PlugCheck*
:PlugCheck [name ...]
        Report which plugins have updates waiting, without taking them. The
        only thing written is what `git fetch` puts inside .git: no checkout,
        no merge, no `do` hooks. Plugins with updates are listed first, with
        the number of new commits and the newest subjects.

        This is the read-only half of |:PlugUpdate|. Without it the only way
        to learn whether anything needed updating was to update everything —
        rewriting every checkout and re-running every `do` hook, which for a
        hook that compiles something is minutes of CPU to be told nothing had
        changed.

        Press u on a row to update just that plugin. Nothing is checked on a
        timer or at startup; a check only happens when you ask for one.

        A `frozen` plugin, and one pinned with `tag` or `commit`, is reported
        as such without touching the network: an update would not move it
        either. The fetch does not pass --depth, so a full clone is not
        narrowed into a shallow one by a read-only question.

        Requires a daemon that announces the `check` capability. If yours does
        not, SimplePlug says so and does nothing rather than sending a request
        it cannot answer.

                                                                   *:PlugDiff*
:PlugDiff [name ...]
        Review what the last update brought in. One section per plugin that
        moved: the commit it moved from, the commit it moved to, and the
        subjects of the commits in between (newest first, at most 50). Merge
        commits are left out. With plugin names, only those are shown.

        Press X on a plugin's header line to roll that plugin back to the
        commit it moved from; q closes the window. An empty subject list does
        not mean nothing happened — a rollback moves HEAD to an ancestor, so
        no commit came in — and the line says so.

        The record is written to g:simpleplug_dir/.simpleplug-lastupdate.json
        when an update finishes, so :PlugDiff still works in the next Vim
        session. Each update merges into that file rather than replacing it:
        rolling one plugin back must not lose the other plugins' previous
        commits. Entries for plugins you no longer declare are dropped. A
        malformed record, or an entry whose commits are not full object IDs,
        is ignored rather than trusted — those commits are handed back to git.

        Requires a daemon that announces the `update_detail` capability
        (protocol 2 and later). After updating SimplePlug itself, run
        ./install.sh and |:PlugRestart| if the record stays empty.

                                                               *:PlugRollback*
:PlugRollback[!] {name}
        Roll one plugin back to the commit its last recorded update moved it
        from — the same thing X does in |:PlugDiff|, without opening the
        window. With [!] it does not ask for confirmation.

        This is an ordinary commit-pinned update, so it inherits that path
        whole: a shallow clone is deepened to reach the commit, submodules are
        re-synced, and a plugin with uncommitted changes is reported `dirty`
        and left alone. A `frozen` plugin is rolled back like any other, for
        the reason given under |:PlugRestore|.

                                                               *:PlugSnapshot*
:PlugSnapshot [file]
        Write the exact commit of every plugin to a snapshot file. Defaults to
        g:simpleplug_dir/simpleplug.snapshot.json.

        The file is meant to be committed to your dotfiles and read in a diff,
        so it is emitted by hand rather than by |json_encode()|: plugins are
        sorted by name and written one per line. Vim's dictionary order is an
        implementation detail, and a one-line file whose keys reshuffle on
        every regeneration cannot be reviewed. Regenerating an unchanged
        checkout produces a byte-identical file.

        Two shapes are written, both read: >

            {"version": 1, "plugins": {
                "name": {"commit": <full-oid>, "url": ..., "branch": ...}}}
            {"name": <full-oid>}
<
        The versioned shape also records where the commit came from, which is
        what lets |:PlugSnapshotDiff| tell a changed declaration from a moved
        checkout. The second is the original shape and stays readable forever.
        A new file uses |g:simpleplug_snapshot_format|; a file being
        overwritten keeps whatever shape it already has, so regenerating a
        lockfile under version control never rewrites it into another format.

        A private 0700 staging directory is atomically claimed beside the
        target on the same filesystem; the complete file is written inside it
        and atomically renamed, so a failed write leaves the previous snapshot
        intact. Pre-existing staging names are skipped without following them.
        A snapshot target that is itself a symbolic link is refused.

                                                           *:PlugSnapshotDiff*
:PlugSnapshotDiff [file]
        Compare registered local checkouts with a snapshot without starting
        the daemon, accessing the network, or changing the snapshot. The
        complete file is validated before any checkout is inspected or output
        is printed. Results are sorted by plugin name and distinguish matched
        entries, commit drift, a plugin sitting on the locked commit but no
        longer declared with the locked url or branch (respecced), a missing
        checkout, a non-Git directory, an unreadable HEAD, a registered plugin
        absent from the snapshot (unlocked), and an unregistered snapshot entry
        (orphaned). The summary line names the shape the file was read as.

        `respecced` needs the url and branch a versioned snapshot records, so a
        legacy snapshot never produces one.

                                                                *:PlugRestore*
:PlugRestore [file]
        Check every plugin out to the commit recorded in a snapshot. Both
        snapshot shapes are accepted. Validation happens before the daemon
        starts: the root must be an object, every entry must have the expected
        type, and each commit must be a full 40-digit SHA-1 or 64-digit
        SHA-256 hexadecimal object ID — a commit reaches git as a revision, so
        one bad entry rejects the whole file rather than part of it. Snapshots
        produced by earlier SimplePlug versions remain readable.

        A `frozen` plugin is restored like any other: freezing means an update
        leaves it alone, not that an explicit restore silently does nothing.

                                                                   *:PlugHook*
:PlugHook {name}
        Re-run a single plugin's `do` post-hook.

                                                                   *:PlugStop*
:PlugStop
        Stop the daemon. It starts again on the next command, which waits for
        the stopped process to actually exit first — a stop is a SIGTERM, and
        a request handed to a daemon that is still on its way out is a request
        nobody answers.

                                                                *:PlugProfile*
:PlugProfile[!]
        Attribute startup cost to the plugin that spent it: every plugin
        SimplePlug has loaded, sorted by descending wall milliseconds, with
        how it was loaded (eager, lazy, install, ftdetect) and, for a lazy
        plugin, the trigger that loaded it. With [!] each sourced file is
        listed with its own measurement.

        The whole justification for `for` and `on` is startup time, so
        annotating plugins without a measurement is guesswork.

        An eager plugin is not sourced by SimplePlug. simpleplug#End() runs
        from your vimrc, and that runs before Vim walks 'runtimepath' for
        plugin/ scripts, so Vim itself does the sourcing. SimplePlug times
        that scan with |SourcePre| and |SourcePost| autocommands over the
        directories it just registered, and drops them again at |VimEnter| so
        that nothing sourced later — an ftplugin, a syntax file — is charged
        to startup. A Vim without those two events reports no eager plugin at
        all rather than a made-up number.

        A `for` plugin's ftdetect/ files are sourced eagerly — otherwise its
        filetype could never be detected and the trigger could never fire — so
        that cost is charged to startup and reported on its own row. It keeps
        that row after the trigger fires and the plugin body loads: the
        startup cost was paid either way. It is often what a lazy plugin
        still costs you.

        The report ends with the eager plugins that cost at least
        |g:simpleplug_profile_threshold_ms|, as candidates for `for` or `on`.

        The numbers are wall clock, not CPU: any I/O a plugin does while
        loading is counted, which is usually what you want to know and never
        what a CPU figure would tell you.

See |simpleplug-daemon| for :PlugHealth, :PlugRestart and :PlugLog.

5. UI KEYS                                                     *simpleplug-ui*

Inside the progress window:

  j, k        move the selection to the next/previous plugin
  <CR>        open the directory of the plugin under the cursor
  d           show that plugin's recent git log in a scratch buffer
  D           open |:PlugDiff| for that plugin: the commits its last update
              brought in, with X to roll it back
  u           update only the plugin under the cursor
  R           retry only the plugins that failed
  S           show status
  /           filter the list
  h, ?        toggle the key help
  q, <Esc>    close

The row under the cursor is resolved from the map built while rendering, so a
plugin whose name is a prefix of another (simpletree and simpletreesitter, say)
resolves to the row you are actually on.

While an operation runs the list is ordered working, then finished, then
waiting, and the spinner redraws it every |g:simpleplug_spinner_interval|
milliseconds. Redraws no longer move the cursor, and once you have selected a
row with j/k the ordering is frozen, so the plugin you are reading stays where
it is until the operation ends.

6. SCRIPTING                                            *simpleplug-scripting*

An install or update reports what it did, so nothing has to watch the progress
window to find out.

                                                       *SimplePlugComplete*
When an operation finishes — including when it fails, and when the daemon dies
mid-flight — SimplePlug sets |g:simpleplug_last_result| and then fires the
|User| autocommand SimplePlugComplete: >

    autocmd User SimplePlugComplete
      \ if g:simpleplug_last_result.errors > 0 | PlugLog | endif
<
The event is fired even when |g:simpleplug_activate_on_install| activation or
helptag generation throws, so a broken plugin — or a typo in your own
|simpleplug#Plug()| options — cannot leave |:PlugInstall!| returning silently
with the previous run's dictionary.

                                                 *g:simpleplug_last_result*
The result of the most recent operation, a dictionary with these keys:

  mode       'install', 'update', 'status', 'clean' or 'hook'
  total      number of plugins the operation covered
  installed  newly cloned
  updated    moved to a new commit
  ok         already up to date, pinned, or hook-only
  frozen     skipped because of `frozen`
  removed    directories :PlugClean deleted
  errors     number of entries in `failed`
  failed     list of {name, message}, sorted by name
  elapsed    wall-clock seconds

                                                     *simpleplug#Await()*
simpleplug#Await([{timeout}])
        Block until the running operation finishes and return the same
        dictionary. {timeout} is in seconds; omitted or negative means
        |g:simpleplug_sync_timeout|. Returns the previous result immediately
        when nothing is running. This is what [!] on |:PlugInstall| uses.

                                                *simpleplug#LastResult()*
simpleplug#LastResult()
        The dictionary above, or an empty one if no operation has finished
        yet.

7. CONFIGURATION                                           *simpleplug-config*

An option documented below as 0 or 1 also accepts |v:false| and |v:true|.
Every option is type/range checked when the plugin loads.  Options consulted
again at runtime (timeouts, jobs and UI sizing/timing) are checked at the use
site too, so a later bad assignment falls back safely instead of escaping from
an autocommand or timer.

                                                            *g:simpleplug_dir*
Plugin directory. Default: ~/.vim/plugged

                                                   *g:simpleplug_daemon_path*
Explicit path to the daemon binary. Default: '' (search 'runtimepath'/lib).

                                                          *g:simpleplug_debug*
Echo daemon traffic as it happens. Default: 0. |:PlugLog| is usually better —
it records everything without needing to be switched on in advance.

                                                   *g:simpleplug_auto_install*
Install newly declared plugins on VimEnter. Default: 1

                                                  *g:simpleplug_window_width*
Width of the progress window. Default: 88

                                                           *g:simpleplug_jobs*
Maximum parallel git operations, 1..64. Default: 8

                                                   *g:simpleplug_git_timeout*
Timeout in seconds for a single git operation. Default: 300

                                                  *g:simpleplug_hook_timeout*
Timeout in seconds for a post-hook. Default: 600

Both timeouts are re-read every time the daemon starts, so changing them takes
effect on the next |:PlugRestart| without restarting Vim.

                                            *g:simpleplug_activate_on_install*
Make a newly installed plugin usable in the running session instead of at the
next Vim start. Default: 1

When an install finishes, each plugin it reports as newly installed is added
to 'runtimepath' and its plugin/ and after/plugin/ scripts are sourced; its
ftdetect/ files are sourced too and already-open buffers are re-detected, so a
filetype the plugin introduces takes effect immediately. A plugin declared
with `for`, `on` or `event` only gets its triggers armed — it stays unloaded
until one of them fires, as usual, unless something eager depends on it (see
|simpleplug-lazy-deps|). A plugin whose directory did not actually appear is
reported and left unloaded.

Anything that goes wrong while a plugin is being activated — a script that
throws, an `on` trigger that is not a usable command name or mapping, a
runtime directory Vim will not take — is reported on that plugin's row and
goes no further. It does not stop the rest of the batch, and it never
suppresses helptag generation or |SimplePlugComplete|.

Set it to 0 if you would rather restart Vim: sourcing third-party code at an
unusual moment can upset a plugin that assumes it loads before |VimEnter|.

                                                  *g:simpleplug_sync_timeout*
How many seconds [!] on |:PlugInstall| / |:PlugUpdate| and |simpleplug#Await()|
will wait before giving up. Default: 1800. The operation itself keeps running.

                                            *g:simpleplug_lazy_event_refire*
Let the occurrence that woke an `event` plugin reach the plugin. Default: 1

The event arrives before the plugin has any handler for it — the handler is
registered by the sourcing that occurrence caused — so without this the first
|InsertEnter| is the one InsertEnter the plugin never sees. Set it to 0 for an
event whose handlers must not run at an unexpected moment, and accept that the
plugin starts taking effect from the next occurrence. Either way the event is
delivered at most once, and no other listener is run twice. See
|simpleplug-lazy-event|.

                                              *g:simpleplug_spinner_interval*
Progress window refresh interval in milliseconds. Default: 200

                                        *g:simpleplug_profile_threshold_ms*
Wall milliseconds at or above which |:PlugProfile| lists an eagerly loaded
plugin as a lazy-loading candidate. Default: 5

                                              *g:simpleplug_snapshot_format*
Shape used for a snapshot file that does not exist yet: "v1" (default, records
url and branch beside the commit) or "legacy" ({plugin-name: full-oid}). A file
being overwritten keeps the shape it already has, whatever this is set to; see
|:PlugSnapshot|.

8. DAEMON SUPERVISION                                      *simpleplug-daemon*

The Rust daemon is managed by simplecore, the supervisor shared by the whole
simple* plugin suite. It is vendored into this repository at
autoload/simpleplug/core.vim; that file is generated, do not edit it in place.

What it guarantees:

- Liveness is always read from |job_status()|. job_start() returns a job
  object even when the exec itself failed, so a daemon that cannot start is
  never mistaken for one that is running.
- A superseded daemon's late exit callback cannot clear the state of the
  replacement that already took its place.
- Output still queued when you stop the daemon is discarded, so an explicit
  stop cannot be undone by an event that was already in flight.
- A daemon that dies is restarted automatically with exponential backoff.
  If it keeps crashing, the supervisor reports it once and stops trying
  rather than respawning forever; :PlugRestart re-arms it.
- Requests are correlated to replies by id and can time out, so a wedged
  daemon never leaves a callback hanging.

                                                                 *:PlugHealth*
:PlugHealth
        Report daemon path, run state, negotiated protocol and capabilities,
        uptime, crash and restart counts, whether the crash-loop breaker has
        tripped, the git executable, the plugin directory and both timeouts.

                                                                *:PlugRestart*
:PlugRestart
        Stop the daemon and start a fresh one. Clears the crash-loop breaker,
        so this is the way back after repeated failures.

                                                                    *:PlugLog*
:PlugLog
        Open the daemon transcript in a scratch buffer: start and exit events,
        restarts, protocol handshakes, send failures and stderr.


==============================================================================
DAEMON COMMAND LINE                                    *simpleplug-daemon-cli*

The daemon takes no arguments in normal use: the plugin starts it and speaks
JSON over its stdin and stdout.  For diagnosis it also answers: >

  simpleplug-daemon --version
  simpleplug-daemon --help
  simpleplug-daemon --self-test
<
--self-test checks the handshake reply serialises and prints "ok".
install.sh runs it on the freshly built binary before replacing a working one,
so a build that compiles but does not work never reaches lib/.

Every daemon in the simple* suite answers these three the same way.

VENDORED SUPERVISOR                                    *simpleplug-simplecore*

The daemon supervisor in autoload/simpleplug/core.vim, and the test harness
beside it, are vendored from the suite's shared .simplecore bundle rather
than written here — each plugin carries its own copy so that installing
this plugin alone is enough.  Do not edit those files in place: >

  make core-verify
<
checks each of them against the sha256 recorded in .simplecore.manifest and
fails the build when one has drifted.  `make check` depends on it.
